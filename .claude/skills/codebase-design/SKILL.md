# 코드 구조의 말과 원칙

목표: **작은 입구 뒤에 많은 일을 숨긴 "깊은 모듈"** 을 만든다. 그러면 고칠 곳이 한 군데로 모이고(국소성), 쓰는 쪽은 적게 알고도 많이 쓰며(지렛대), 테스트는 입구 하나로 끝난다.
사용자는 코딩 초보다. 사용자에게 말할 때는 아래 말에 괄호 풀이를 붙인다 (예: "모듈(코드 한 덩어리)").

## 말 (이 단어만 쓴다)
| 말 | 뜻 | 쓰지 않는 말 |
|----|----|------------|
| **모듈** | 입구와 속이 있는 코드 덩어리. 함수 하나든 파일 하나든 크기 무관 | 컴포넌트, 서비스 |
| **인터페이스**(입구) | 쓰는 쪽이 알아야 하는 전부 — 함수 모양뿐 아니라 순서·오류·필요한 설정까지 | API, 시그니처 |
| **구현**(속) | 모듈 안의 실제 코드 | |
| **깊이** | 입구 하나로 할 수 있는 일의 양. 입구는 작고 속이 크면 **깊다**, 입구가 속만큼 복잡하면 **얕다** | |
| **이음매**(seam) | 속을 고치지 않고 동작을 바꿔 끼울 수 있는 자리 = 인터페이스가 놓인 곳 | 경계 |
| **어댑터** | 이음매에 끼워져 인터페이스를 채우는 실제 부품 (예: 진짜 Supabase 저장 / 테스트용 가짜 저장) | |
| **지렛대** | 쓰는 쪽이 얻는 것 — 하나를 배워 여러 곳에서 씀 | |
| **국소성** | 고치는 쪽이 얻는 것 — 변경·버그·확인이 한 곳에 모임 | |

## 원칙
- **깊이는 입구의 성질이다.** 속은 작은 조각으로 나뉘어도 되지만 그 조각을 입구로 내보내지 않는다.
- **삭제 시험** — 이 모듈을 지운다고 상상한다. 복잡함이 사라지면 그냥 통과만 시키던 얕은 모듈(없애도 됨). 복잡함이 여러 호출하는 곳으로 퍼지면 제 역할을 하던 모듈.
- **인터페이스가 곧 테스트 면** — 테스트도 쓰는 쪽과 같은 입구로 들어간다. 입구를 건너뛰어 속을 테스트하고 싶다면 모듈 모양이 잘못된 것.
- **어댑터 하나면 가짜 이음매, 둘이면 진짜** — 실제로 바꿔 끼울 것(운영용 + 테스트용)이 둘 이상일 때만 이음매를 만든다.

## 테스트하기 쉬운 모양
1. 필요한 것을 **받아서** 쓴다 (안에서 직접 만들지 않는다): `saveRecord(rec, store)` ○ / 안에서 `supabase` 를 직접 부름 ✗
2. 결과를 **돌려준다** (밖을 몰래 바꾸지 않는다): `calcAngle(points) → 18.4` ○ / 화면 글자를 직접 바꿈 ✗
3. 입구는 작게 — 함수 수·인자 수가 적을수록 테스트가 쉽다.

## 의존성 4종류 → 테스트 방법
| 종류 | 예 (이 사업의 앱) | 테스트 |
|------|-----------------|--------|
| 1. 안에서만 계산 | 각도·점수·회차 계산 | 바로 합쳐서 입구로 테스트 (`js/logic/` + `node --test`) |
| 2. 기기 안 저장 | IndexedDB, localStorage | 테스트용 가짜 저장소로 대신 |
| 3. 내 서버 | Supabase 표·Edge Function | 입구(포트)를 정하고 운영용·테스트용 어댑터 2개 |
| 4. 남의 서비스 | Google Play 결제, 카카오 로그인 | 가짜 어댑터로 대신 |

## 바꿀 때: 겹쳐 쌓지 말고 바꿔 끼우기
- 깊어진 모듈의 입구에 새 테스트를 쓰고, 얕은 조각마다 있던 옛 테스트는 지운다.
- 테스트는 입구로 보이는 결과만 확인한다. 속을 고쳐도 테스트가 그대로 통과해야 한다.
- 이 사업의 앱은 빌드 없는 HTML+JS(ADR-000-1)다. 큰 `index.html` 은 계산부터 `js/logic/*.js` 로 하나씩 옮기는 방식(한 번에 한 모듈, 매번 테스트 통과 확인).
