# 질문으로 다듬기 + 문서 남기기

## 1. 질문하는 법 — 결정 나무를 라운드로
- 정할 것들을 **결정 나무**로 본다: 한 결정이 정해져야 다음 결정들이 열린다.
- **지금 물을 수 있는 질문**(앞 결정이 이미 정해진 것) 전부를 **한 라운드에 한꺼번에** 묻는다. 번호를 붙이고 각각 **추천 답**을 단다. 그리고 답을 기다린다.
- 다른 질문 답에 따라 달라지는 질문은 다음 라운드로 미룬다.
- "네" 라고만 답하면 추천 답을 받아들이는 뜻이 되게 묻는다.

형식:
```
❓ **Q1 — {질문 제목}**: {질문. 필요하면 선택지 A/B/C}
➡️ 추천: {추천 답과 이유 한 줄}

---

❓ **Q2 — …**
```
- **사실은 직접 찾는다.** 코드·문서·설정에서 알 수 있는 것은 사용자에게 묻지 않고 찾아본다(오래 걸리면 서브에이전트에 맡기고, 그 결과에 걸린 질문만 다음 라운드로). **결정은 사용자에게** 묻는다.
- 한 라운드는 질문 5개 이하로 (초보자 부담). 넘치면 중요한 것부터.
- 정할 것이 더 없으면 끝. 마지막에 정해진 것을 표(| 결정 | 내용 | 이유 |)로 보여 주고 "이대로 맞나요?" 확인을 받기 전에는 아무것도 만들지 않는다.

## 2. 대화하면서 바로 하는 문서 일
### 용어 — `docs/GLOSSARY.md` 의 "## 이 앱의 말 (도메인 용어)"
- 사용자 말이 기존 용어와 다르게 쓰이면 바로 짚는다: "용어집에서 '회차' 는 X 인데, 지금은 Y 뜻으로 쓰신 것 같아요. 어느 쪽인가요?"
- 뜻이 흐린 말(예: '기록' 이 측정 한 번인지, 회원 전체 이력인지)은 정확한 말을 제안한다.
- 경계를 묻는 **구체적 상황**을 만들어 본다: "회원을 삭제하면 공유 링크로 보낸 리포트는 '기록' 인가요, 아닌가요?"
- 사용자 말과 코드가 다르면 알린다: "코드는 회원 삭제 때 사진을 남기는데, 방금 다 지워진다고 하셨어요. 어느 쪽이 맞나요?"
- 용어가 정해지면 **그 자리에서** 적는다(모아 두지 않는다). 섹션이 없으면 만든다. 형식:
  ```
  - **회차**: 한 회원이 같은 날 같은 방향으로 찍은 측정 한 묶음. _피할 말_: 차수, 세션
  ```
  정의는 1~2문장, "무엇인가" 만. 구현 방법·화면 설명은 쓰지 않는다. 일반 프로그래밍 용어는 넣지 않는다(그건 위쪽 표).

### 결정 — `docs/ADR.md` 의 "## 이 프로젝트의 ADR"
아래 **셋 다** 맞을 때만 "ADR 로 남길까요?" 라고 묻고, 답을 받으면 다음 번호로 적는다:
1. **되돌리기 어렵다** — 나중에 바꾸는 비용이 크다
2. **설명 없으면 이상해 보인다** — 나중에 "왜 이렇게 했지?" 할 만하다
3. **진짜 선택이었다** — 다른 길이 있었고 이유가 있어 골랐다
형식은 기존 ADR 과 같게: `### ADR-NNN: 제목` / **결정** / **이유** / **트레이드오프**. 하나라도 아니면 ADR 을 만들지 않는다.

## 3. 끝난 뒤
- 구현이 필요하면 `/plan` 으로 계획서를 만들자고 안내한다 (바로 코드부터 쓰지 않는다).
- 떠오른 다른 일은 `docs/BACKLOG.md` 로.
