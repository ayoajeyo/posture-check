기능 하나를 끝까지 만든다. 사용자는 코딩 초보다. 각 단계의 결과를 짧게 보여 주고, **결정이 필요한 곳에서만** 멈춘다.

기능: $ARGUMENTS

## 절차
1. **파악** — `CLAUDE.md`, `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/DATA.md` 와 관련 코드를 읽는다. 이 기능이 PRD 범위 밖이면 먼저 말한다.
2. **설계** — `architect` 에이전트로 설계안을 받는다. 단계가 4개를 넘거나 ADR 변경이 필요하면 사용자에게 보여 주고 승인을 받는다. 그 외에는 설계안 요약(5줄)만 보여 주고 진행한다.
3. **데이터** — 새 필드가 있으면 `docs/DATA.md` 에 먼저 추가한다(등급·보관·삭제 포함).
4. **테스트 먼저** — 계산 로직이 있으면 `tester` 에이전트로 실패하는 테스트를 만든다.
5. **구현** — 단계별로 만든다. `clean-ui` 등 관련 스킬을 따른다. 한 단계 끝날 때마다 `node --check`·테스트를 돌린다.
6. **검토** — `reviewer` 에이전트. 🔴 가 있으면 고치고 다시 검토(최대 2회). 개인정보를 다루면 `privacy-guard`, 화면이 있으면 `ui-checker` 도 실행.
7. **문서** — `docs-keeper` 에이전트로 CHANGELOG(미출시 항목)·DATA·TESTING(수동 점검 항목)·BACKLOG 갱신.
8. **커밋** — `feat: {기능 요약}` 로 커밋. push 는 하지 않는다(배포는 `/ship`).
9. **보고** — 아래 형식.

## 보고 형식
```
## 완료: {기능}
**달라지는 것**: (사용자 입장 2줄)
**바뀐 파일**: 표 | 파일 | 무엇을 |
**직접 확인하는 법**: 폰에서 {화면} → {행동} → {보여야 할 것}
**검토 결과**: reviewer ✅ / privacy-guard ✅ / ui-checker ✅ (문제 있으면 요약)
**다음**: `/ship` 으로 배포하거나, 더 고칠 점을 말씀해 주세요.
```

## 금지
- 요청하지 않은 기능을 끼워 넣지 마라. 떠오른 아이디어는 BACKLOG.md "다음" 에 적어라.
- 테스트를 통과시키려고 테스트를 약하게 고치지 마라.
