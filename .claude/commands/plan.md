`plan-gate` 스킬의 양식대로 **계획서만** 만든다. 코드·서버·설정은 건드리지 않는다. 사용자는 코딩 초보다.

대상: $ARGUMENTS

## 절차
1. `CLAUDE.md`, `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/DATA.md`, `docs/ADR.md` 와 관련 코드를 **읽기만** 한다.
2. `plan-gate` 스킬 1번 표로 **승인 필수 여부**를 판정해 근거 한 줄과 함께 알린다.
3. 새 기능이면 `architect` 에이전트, 버그면 `debugger` 에이전트로 설계·원인을 받는다.
4. `docs/PLANS/오늘날짜-제목.md` 를 만든다(제목은 영문·숫자·`-`, 한글이면 그대로 가능). 상태는 `초안`.
5. 사용자에게 아래 요약을 보여 주고 **멈춘다**.
6. "승인" 을 받으면 상태를 `승인됨`, 승인일을 적고 `docs: 계획 {제목}` 로 커밋한다(push 는 하지 않는다).
7. 다음 단계를 안내한다: `/feature 계획: docs/PLANS/{파일}` 또는 `/fix 계획: docs/PLANS/{파일}`.

## 요약 형식
```
## 계획: {제목}   (승인 필수 ✅ / 불필요 — 이유)
**한 줄 목적**: …
| 바뀌는 곳 | 무엇을 |
**위험**: 가장 큰 것 1~2개 + 되돌리는 법
**단계**: 1) … 2) … (각 단계의 확인 방법)
**질문** (추천 답 포함): …
**승인하시면** "승인" 이라고 답해 주세요. 고치고 싶은 곳은 번호로 알려 주세요.
```

## 금지
- 승인 전에는 코드, 서버, 설정 파일을 바꾸지 마라. 계획서 파일 하나만 만든다.
- 계획서에 실제 회원 정보를 쓰지 마라.
