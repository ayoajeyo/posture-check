# 계획: git 기록에서 회원 실명 지우기
상태: 초안        (초안 → 승인됨 → 진행 중 → 완료 / 폐기)
요청: "지워죠" (예전 커밋 설명에 남은 회원 실명 삭제)
작성일: 2026-10-17   승인일: -

## 한 줄 목적
공개 저장소(GitHub)의 지난 기록(커밋 설명·옛 파일 내용)에 남아 있는 회원 실명을 지운다. 앱 동작·데이터는 바뀌지 않는다.

## 확인된 범위 (이름은 이 문서에 적지 않음)
| 어디에 | 몇 곳 | 비고 |
|---|---|---|
| 커밋 설명(메시지) | 회원 2명 · 커밋 2개 (2026-10-13 v233, 2026-10-14 v251) | 처음 알린 1건 + 점검 중 1건 더 발견 |
| 옛 파일 내용(지금은 지워진 주석·learn_v203.json) | 회원 2명 · 2026-10-13~15 사이 커밋들 | 2026-10-15 에 파일에서는 지웠지만 기록에는 남아 있음 |
| 지금 파일 | 없음 | |
| 다른 이름 | 모름 | 아요가 회원 이름 목록을 주면 같이 검사 |

## 하는 것
1. 이름 목록(아요가 채팅으로 줌, 저장소에 저장하지 않음)으로 **모든 브랜치의 기록 전체**에서 커밋 설명·파일 내용의 이름을 `회원` 으로 바꿔 기록을 다시 쓴다 (git filter-repo / filter-branch).
2. 다시 쓴 기록을 GitHub 에 강제로 올린다 (main · ccr-628a0d3c-ppeiga · release-v264 · ccr-e9070da6-ckxa8b).
3. 올린 뒤 기록 전체에서 이름이 0건인지 다시 검사.

## 하지 않는 것
- 앱 코드·회원 데이터·서버(Supabase) 변경 없음.

## 위험과 되돌리는 법
| 위험 | 일어날 때 | 대응 |
|---|---|---|
| **되돌릴 수 없음** | 강제 올리기 후 | 되돌리면 이름이 다시 들어가므로 되돌리지 않는다 |
| 2026-10-13 이후 커밋 번호(약 200개+)가 모두 바뀜 | 병원·집 PC 의 예전 복사본 | 두 PC 는 `git pull` 대신 **새로 받기**(아래 안내) 필요. 예전 복사본에서 push 하면 이름이 되살아남 |
| GitHub 가 옛 커밋을 번호로 한동안 보여 줄 수 있음 | 누군가 옛 번호를 알면 | GitHub 지원팀에 '민감 정보 삭제' 요청을 아요가 직접(계정 주인만 가능) |
| 이미 누가 복사(fork·clone)했다면 그쪽엔 남음 | 공개 기간 동안 | 막을 방법 없음 |
| GitHub 가 강제 올리기를 막으면 | main 보호 설정 | 멈추고 알림 |
| 배포(GitHub Pages) | main 강제 올리기 | 파일 내용은 같아 화면 변화 없음, 다시 빌드만 됨 |

## 단계
1. 아요가 이름 목록 주기 + 이 계획 승인
2. 현재 상태 백업(이 세션 임시 폴더에만, 끝나면 삭제) → 기록 다시 쓰기 → 이름 0건 검사
3. 네 브랜치 강제 올리기 → GitHub 에서 다시 검사
4. 두 PC 새로 받기 안내 · GitHub 지원팀 요청 방법 안내
