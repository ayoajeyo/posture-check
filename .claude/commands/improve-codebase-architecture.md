코드 구조의 불편한 곳을 찾아 **깊게 만들 후보**(얕은 조각들을 작은 입구 뒤로 모으는 정리)를 제안한다. 목적은 테스트하기 쉽고 AI 가 길을 잃지 않는 코드. 이 명령은 **보고와 질문까지만** 하고 코드를 고치지 않는다. 사용자는 코딩 초보다.

살펴볼 곳: $ARGUMENTS

먼저 `codebase-design` 스킬을 읽고 그 말(모듈·인터페이스·깊이·이음매·어댑터·지렛대·국소성)만 쓴다. 사용자에게는 괄호 풀이를 붙인다.

## 1. 살펴보기
- **범위부터 정한다 (필요 없는 곳은 안 본다).** 사용자가 정해 줬으면 그곳만. 아니면 `git log --oneline -60 --name-only` 로 **최근 자주 고친 파일·부분**을 찾아 거기부터. 큰 파일(`index.html` 등)은 자주 고친 함수 이름 위주로.
- `docs/GLOSSARY.md`(이 앱의 말), `docs/ADR.md`(이미 정한 것 — 다시 따지지 않음), `docs/ARCHITECTURE.md`, `docs/BACKLOG.md` 를 먼저 읽는다.
- 코드 훑기는 **서브에이전트(Explore)** 에게 맡겨 메인 대화를 가볍게 유지한다. 볼 것:
  - 한 가지를 이해하려고 여러 곳을 오가야 하는가
  - 입구가 속만큼 복잡한 **얕은** 모듈이 있는가 (삭제 시험)
  - 테스트하려고 떼어 낸 함수가 정작 버그 나는 "부르는 쪽" 과 떨어져 있는가 (국소성 없음)
  - 서로 얽혀 이음매 너머로 새는 곳 (예: 화면 코드가 Supabase 를 직접 부름)
  - 테스트가 없거나, 지금 입구로는 테스트하기 어려운 곳 (index.html 문자열을 잘라 테스트하는 곳 등)
- 개인정보: 보고서·대화에 회원 실명·연락처를 쓰지 않는다. 코드 속 예시 데이터를 옮길 때도 가짜 이름으로.

## 2. 그림 보고서 (HTML)
- 저장소 **밖** 임시 폴더에 한 파일로 만든다: Windows 는 `%TEMP%\architecture-review-YYYYMMDD-HHMM.html`, 그 밖은 `$TMPDIR` 또는 `/tmp`. 연다: Windows `start "" "경로"`, macOS `open`, Linux `xdg-open`. 전체 경로를 알려 준다.
- 혼자 열리는 HTML. 스타일은 `<style>` 로 직접(네이비 `#1E2A4A` 하나 + 빨강 새는 곳 + 주황 주의). 관계도는 Mermaid: `<script type="module">import mermaid from "https://cdn.jsdelivr.net/npm/mermaid@11.4.1/dist/mermaid.esm.min.mjs"; mermaid.initialize({startOnLoad:true, theme:"neutral"});</script>` 와 `<pre class="mermaid">…</pre>`.
- 맨 위: 저장소 이름·날짜·범례(네모 = 모듈, 점선 = 이음매, 빨간 화살표 = 새는 곳, 굵은 네모 = 깊은 모듈). 소개 문단 없이 바로 후보.
- 후보마다 카드 하나:
  - **제목** (무엇을 깊게 하나, 예: "회차 계산을 한 모듈로")
  - **추천 강도** 배지: 강력 추천 / 검토할 만함 / 가능성만 + **의존성 종류**(1 안에서만 계산 · 2 기기 저장 · 3 내 서버 · 4 남의 서비스)
  - **파일**: 고정폭 글꼴 목록 (함수 이름 포함)
  - **전 / 후 그림** (나란히, 높이 320px 안팎) — 이것이 핵심. 문단 설명 대신 그림.
  - **문제** 한 문장 / **바뀌는 것** 한 문장 / **얻는 것** 짧은 항목(국소성·지렛대·테스트 말로)
  - ADR 과 부딪히면 주황 상자 한 줄: "ADR-011 과 다르지만 다시 볼 만한 이유: …" (실제로 불편이 클 때만)
- 맨 끝 **가장 먼저 할 것**: 후보 하나와 이유 한 문장.
- 인터페이스 설계안은 아직 내지 않는다. 보고서를 연 뒤 묻는다: **"어느 후보를 같이 살펴볼까요?"**

## 3. 고른 후보 다듬기
- `doc-grilling` 스킬로 결정 나무를 라운드로 묻는다: 지켜야 할 것, 의존성, 깊어진 모듈의 모양, 이음매 뒤에 둘 것, 남길 테스트.
- 그 자리에서: 새 모듈 이름이 이 앱의 말이면 `docs/GLOSSARY.md` 에 추가. 사용자가 무거운 이유로 후보를 거절하면 "다음 점검 때 다시 제안하지 않게 ADR 로 남길까요?" (일시적 이유면 묻지 않음).
- 인터페이스를 여러 모양으로 비교하고 싶으면 서브에이전트 2~3개에 서로 매우 다른 설계를 맡겨 깊이·국소성·이음매 위치로 비교한다.
- 다듬기가 끝나면 **`/plan` 으로 계획서**를 만든다(구조 변경은 `plan-gate` 6번 "큰 변경" 에 해당하는 경우가 많다). 남은 후보는 `docs/BACKLOG.md` "다음" 에 한 줄씩.

## 금지
- 코드 수정, 파일 이동. 이 명령이 쓰는 것은 임시 폴더의 보고서와 (사용자 확인 후) `docs/GLOSSARY.md`·`docs/ADR.md`·`docs/BACKLOG.md` 뿐.
- 보고서를 저장소 안에 저장하거나 커밋.
- 이론상 가능한 모든 리팩터 나열 — 최근 자주 고친 곳 위주로 3~6개.
