# 데이터 사전: {프로젝트명}

> 이 앱이 다루는 **모든 데이터**를 적는다. 개인정보 보호의 출발점이고, `privacy-guard` 와 `/privacy-policy` 가 이 문서를 읽는다.
> 새 필드를 추가하면 코드보다 먼저 여기에 적는다.

## 1. 민감도 등급
| 등급 | 뜻 | 예 | 취급 |
|------|----|----|------|
| S3 매우 높음 | 유출 시 개인 피해 큼 | 신체 사진, 서명, 건강 상태 메모 | 암호화 저장소·비공개 버킷·서명 URL. 로그 금지. 기본 보관 기간 제한 |
| S2 높음 | 개인 식별 가능 | 이름, 연락처, 출생연도, 회원번호+이름 조합 | 로그 금지. 본인(센터)만 접근 |
| S1 낮음 | 식별 불가 | 측정 각도 숫자(이름 없이), 앱 설정 | 일반 취급 |

## 3. 관계
```
{member 1 ─ N measurement 1 ─ N photo}
```
회원을 지우면 측정과 사진도 지운다(연쇄 삭제). Supabase 면 `ON DELETE CASCADE`.

## 4. 서버 저장 시 (Supabase 를 쓰는 경우만)
| 테이블/버킷 | RLS 규칙 | 비고 |
|---|---|---|
| `members` | `owner_id = auth.uid()` 인 행만 읽기·쓰기 | |
| `measurements` | 위와 같음 | |
| 버킷 `photos` (비공개) | 경로 `<owner_id>/...` 본인만. 읽기는 서명 URL 60초 | 공개 버킷 금지 |

## 5. 내보내기·가져오기
- 사용자가 자기 데이터 전체를 JSON(+사진 zip)으로 내보낼 수 있다. 파일명 규칙: `<앱이름>_backup_2026.10.14.json`
- 가져오기는 같은 형식만. 덮어쓰기 전 확인 팝업.

## 6. 예시 데이터 규칙
테스트·시연에는 가짜만: 이름 `홍길동`·`김예시`, 전화 `010-0000-0000`, 사진은 마네킹·일러스트. 실제 회원 데이터를 테스트에 쓰지 않는다.
