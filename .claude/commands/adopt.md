기존 프로젝트에 하네스가 복사된 직후 실행한다(`scripts/adopt.ps1` 로 복사). 코드는 **건드리지 않고** 문서만 만든다.

대상: $ARGUMENTS

## 절차
1. 전체 파일 구조와 주요 파일(`index.html`, `js/*`, `manifest.json`, `sw.js`, `package.json`)을 읽는다. 큰 파일은 함수 목록 위주로.
2. 다음 문서의 빈칸을 **코드에서 확인한 사실로** 채운다. 확인 안 되는 것은 `{확인 필요: 질문}` 으로 남긴다.
   - `CLAUDE.md` 기술 스택·명령어
   - `docs/PRD.md` 화면 목록·핵심 기능(실제 있는 것만)
   - `docs/ARCHITECTURE.md` 실제 폴더 구조·데이터 흐름·외부 서비스
   - `docs/DATA.md` localStorage/IndexedDB/Supabase 에 저장하는 모든 키 → 등급 추정
   - `docs/ADR.md` 코드에서 드러나는 결정(예: 프레임워크 없음, GitHub Pages)을 "채택됨(기존)" 으로
   - `docs/RELEASE.md` 현재 버전 번호, 패키지 이름
   - `docs/CHANGELOG.md` `git log` 최근 20개를 사용자 말로 요약해 "v{현재} 이전" 항목
3. **차이 보고** — 하네스 표준과 다른 점을 표로: | 항목 | 현재 | 표준 | 바꿀지 |
   예: 버전이 한 곳에만 있음 / 비밀키가 코드에 있음(🔴) / 삭제 시 사진이 남음 / 버튼 이름 불일치.
4. 🔴 항목은 BACKLOG "지금" 에, 나머지는 "다음" 에 넣는다.
5. 사용자에게 `{확인 필요}` 질문을 **한 번에 최대 5개** 묻는다.

## 금지
- 코드를 리팩터링하지 마라. 이 명령은 문서화와 진단만 한다.
- 기존 동작을 추측으로 단정하지 마라. 못 읽은 건 "확인 필요".
