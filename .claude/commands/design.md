화면 시안을 2~3개 만들어 사용자가 **보고 고르게** 한다. 사용자는 코딩 초보다. 말로 설명하기 어려운 취향을 고르기로 알아내는 것이 목적이다.

대상 화면: $ARGUMENTS

## 절차
1. **읽기** — `docs/UI_GUIDE.md`(기본), `docs/TASTE.md`(사용자 취향 — 부딪히면 사용자에게 묻기), 있으면 `design-system/styleguide.html`, `ui-polish`·`clean-ui` 스킬, 측정 화면이면 `measure-viz`. 지금 앱에 같은 화면이 있으면 그 코드와 캡처(`python scripts/screenshot.py …`)를 먼저 본다.
2. **방향 정하기** — 시안끼리 **구성**이 달라야 한다(배치·위계·밀도·정보 순서). 브랜드 색·글꼴·버튼 모양은 셋 다 같다. 예: A 숫자 중심 / B 목록 중심 / C 사진 중심. 각 시안의 한 줄 콘셉트를 정한다.
3. **만들기** — `design/{영문-이름}/a.html`, `b.html`(, `c.html`) 을 만든다.
   - 각 파일은 혼자 열리는 HTML. `<link>` 로 Pretendard 와 `../../design-system/tokens.css` 를 건다(`design/{이름}/` 에서 두 단계 위). `design-system/` 이 없는 앱이면 `clean-ui` 스킬의 `:root` 변수와 UI_GUIDE 5번 표로 `<style>` 을 직접 쓴다.
   - 자기 CSS 가 있는 기존 앱이면, 시안이 앱의 실제 모양과 너무 달라지지 않게 앱 화면 캡처를 옆에 두고 만든다.
   - 내용은 **가짜 데이터**(홍길동, 010-0000-0000, 그럴듯한 측정값). 실제 회원 정보 금지.
   - 390px 폰 화면 하나 분량. 견본의 클래스를 그대로 쓴다.
   - `design/{이름}/index.html` 비교 페이지: 시안을 390×844 iframe 으로 나란히, 위에 각 시안 이름과 콘셉트.
4. **캡처·자가 점검** — 시안마다 `python scripts/screenshot.py design/{이름}/a.html --name {이름}-a` 로 찍어 Read 로 본다. 가로 스크롤·잘림·겹침이 있으면 고친다. 캡처 도구가 없으면 그렇다고 알리고 계속한다.
5. **보여 주기** — 아래 형식으로 보여 주고 **멈춘다**.
6. **고른 뒤** — 사용자가 고르거나 섞으면("A 위쪽 + C 목록"):
   - `docs/TASTE.md` 기록 표에 한 줄: 날짜 · 화면 · 고른 것 · 사용자 말 그대로 · 앞으로의 규칙(한 줄로 일반화).
   - 섞으라고 하면 `design/{이름}/final.html` 을 만들어 다시 보여 준다.
   - `docs: 시안 {이름} — {선택}` 로 커밋(시안 파일 + TASTE.md). push 는 하지 않는다.
   - 다음 단계 안내: `/feature {화면} — design/{이름}/{선택}.html 시안대로`.

## 보여 주기 형식
```
## 시안: {화면}
| 시안 | 콘셉트 | 좋은 점 | 아쉬운 점 |
|------|-------|--------|----------|
| A | 숫자 중심 — 점수를 크게 | 한눈에 결과 | 항목 비교는 스크롤 |
캡처: .shots/{이름}-a-390.png …
**한 번에 보기**: 이 앱 폴더에서 `python -m http.server 8000` → 브라우저로 http://localhost:8000/design/{이름}/
**고르는 법**: "A", 또는 "A 위쪽 + C 목록" 처럼 섞어도 됩니다. 마음에 드는/안 드는 이유를 한마디 덧붙이면 다음 화면부터 반영합니다.
```

## 참고
- `design/` 폴더도 저장소에 커밋되므로 GitHub Pages 에 공개된다. 그래서 시안에는 **가짜 데이터만** 쓴다.
- 시안 캡처는 `.shots/` 에 저장되고 git 에는 올라가지 않는다.

## 금지
- 앱 코드(index.html·js·css)를 바꾸지 마라. 이 명령은 `design/` 과 `docs/TASTE.md` 만 쓴다.
- 시안끼리 색만 다르게 만들지 마라. 구성이 달라야 고를 의미가 있다.
- UI_GUIDE 금지 목록(그라데이션·블러·보라·이모지 아이콘)을 시안에서도 쓰지 마라.
