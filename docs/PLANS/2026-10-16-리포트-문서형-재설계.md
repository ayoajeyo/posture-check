## 한 줄 목적
리포트를 **검사 결과지 같은 A4 문서 한 벌**(8개 섹션, 3쪽 안팎)로 바꾼다. 화면·저장 이미지·PDF·공유 링크가 전부 같은 양식이고, 항목마다 자리가 하나씩이라(요약 → 변화 그래프 → 상세 → 사진 → 기록표) 수치가 반복되지 않는다. 색은 네이비 하나, 판정에만 초록·주황·빨강.

## 데이터 영향
- 새 필드·표·localStorage 키 **없음**. 머리글의 센터명·연락처·주소는 설정(`getSettings()`·센터 소개 `cpAddr`)에서, 담당은 회원 `staff` 에서 읽는다. 비어 있으면 그 칸은 숨긴다.
- 공유 이미지에 들어가는 정보 종류는 전과 같다(회원 이름·사진·수치·판정). 소견 문장은 수치에서 규칙으로 만든다(개인정보 추가 없음).
- 비운 기록은 빈 칸(선 끊김), 0 으로 쓰지 않는다.

## 핵심 설계 결정
| 결정 | 이유 |
|---|---|
| 화면 = HTML/SVG, 이미지 = 캔버스, **데이터는 `report-model.js` 한 곳** | 글꼴이 깨지지 않는 검증된 경로(캔버스)를 유지하면서 수치·판정·순서가 둘 사이에서 어긋날 수 없게 |
| 회차·판정은 기존 `mbBuildSessions`·`buildTimeline`·`judge.js` 그대로 | 회차 번호·판정 색이 앱 어디서나 같게. 새 임계값 없음 |
| 좌/우를 색이 아니라 **줄(라벨 '좌'·'우')로 구분**, 색은 네이비 하나 | 브랜드 네이비는 채도가 낮아 2색 계열 팔레트 검증(validate_palette)을 통과하지 못함 → 색 대신 위치·글자로 구분 (dataviz: 단일 계열은 범례 불필요) |
| 1차 값은 ○(회색 테두리), 선택 회차는 ●(네이비) — 모든 그래프 공통 | "전 → 후" 기호를 한 가지로 통일 |
| 섹션 번호 01~08 | 문서 안 순서가 곧 읽는 순서(요약 → 변화 → 상세 → 사진 → 기록 → 기준) |
| 한 줄 소견은 규칙 기반 | "좋아진 항목 n개 · 정상 들어온 항목 · 기준까지 남은 양" 세 조각을 수치에서 조립. 담당자 자유 입력은 범위 밖 |
