대화가 길어졌거나 작업을 멈출 때 쓴다. 목적은 **다음 대화가 이 대화를 다시 읽지 않고 이 문서 한 장으로 이어가게** 하는 것(토큰 절약 + 병원·집 PC 이동). 사용자는 코딩 초보다.

추가 메모: $ARGUMENTS

## 절차
1. **모으기** — 이번 대화에서 한 일, `git status`·`git log --oneline -10`, `docs/PLANS/` 의 `진행 중`·`초안` 계획, BACKLOG "지금" 을 확인한다.
2. **쓰기** — `docs/HANDOFF.md` 를 **덮어쓴다**(지난 내용은 지운다). 양식은 파일의 제목들을 그대로 쓴다.
   - `상태:` 이어서 할 일이 있으면 `진행 중`, 다 끝났으면 `완료`.
   - `갱신:` `YYYY-MM-DD HH:MM (집 PC / 병원 PC — 사용자에게 묻지 말고 모르면 생략)`.
   - **다음 할 일**은 순서대로, 각 줄에 바로 입력할 명령을 붙인다. 예: `1. 회원 삭제 계획 승인받기 — /plan … 의 계획서 docs/PLANS/2026-10-17-….md 요약 보여주기`.
   - **정해진 것 / 결정 대기**: 사용자가 정한 것과 아직 답을 기다리는 질문.
   - **주의할 점**: 건드리면 안 되는 것, 막힌 이유, 실패한 시도(다시 하지 않게).
   - 전체 60줄 이내. 대화 요약이 아니라 **다음 사람이 바로 움직일 정보**만. 회원 실명·연락처·비밀키 금지.
3. **저장 안 된 코드가 있으면** — 테스트(`npm test`·`node --check`)가 통과하면 평소처럼 커밋한다. 통과하지 않는 반쯤 된 코드면 사용자에게 두 가지를 보여 주고 고르게 한다: (A) `wip/YYYY-MM-DD-주제` 브랜치에 커밋해 올리기(추천 — main 과 배포는 그대로), (B) 이 PC 에만 두기. 고른 내용을 HANDOFF "주의할 점" 에 적는다.
4. **올리기** — `docs: 인수인계 갱신` 로 커밋하고 `/sync` 절차(pull → push)로 올린다. 문서만 바뀐 커밋이라 앱 화면은 그대로다.
5. **안내** — 아래 형식으로 짧게 알린다.

## 안내 형식
```
## 인수인계 저장: docs/HANDOFF.md (상태: 진행 중)
다음 할 일: 1) … 2) …
이제 `/clear` 로 대화를 비우고 새로 시작해도 됩니다. 다음 대화나 다른 PC 에서 Claude Code 를 켜면 이 내용이 자동으로 뜹니다.
```

## 금지
- 대화 전체를 옮겨 적지 마라 (다시 길어진다).
- 반쯤 된 코드를 묻지 않고 main 에 올리지 마라.
