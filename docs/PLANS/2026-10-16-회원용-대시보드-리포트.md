## 한 줄 목적
리포트 맨 위에 **회차별 변화가 한눈에 보이는 요약 카드**가 생긴다 — 핵심 숫자 4개(종합 점수·거북목·척추 균형·ROM 평균)의 추이, 항목×회차 상태표, ROM 1차→최근 그래프. 회원이 "얼마나 좋아졌나" 를 숫자보다 **색과 선으로** 읽을 수 있다. 저장·공유 이미지에도 같은 카드가 들어간다.

## 범위
- 하는 것
  - 리포트 화면(`#view-report`) 회차 선택 **바로 아래**에 "한눈에 보기" 카드 추가 (기존 사진·표·전후 비교는 그대로 아래에 둠)
  - KPI 타일 4개: 종합 점수 · 거북목 CVA · 척추 균형 ATR · ROM 평균(정상 대비 %) — 미니 추이 그래프 + "1차 대비 ▲▼" + 판정 배지
  - 항목 × 회차 상태표: 칸 색 = 그 회차 판정(양호/주의/개선 필요), 숫자 = 측정값. 열은 최대 5개
  - ROM 1차 → 최근 아령 그래프(정상 대비 %) + "숫자로 보기" 토글(기본 접힘)
  - 회차 선택에 따라 **1차~선택 회차**까지만 표시 (3차를 공유하면 4·5차가 섞이지 않음)
  - 회차 1개뿐인 회원(가장 흔함): 추이 대신 "첫 측정" 값·판정만
  - [리포트 이미지 저장]·[공유 링크] 이미지 1쪽에 "머리글 → 한눈에 보기 → 사진" 순서로 포함
  - 계산 로직은 `js/logic/` 순수 모듈 + 테스트 (ADR-011)
- 하지 않는 것 (→ BACKLOG)
  - 기존 리포트 구역(사진·ROM 표·척추 균형·전후 비교) 교체·접기
  - 공유 링크를 이미지 대신 HTML 로 바꾸기 (서버·ADR 필요 — 나중에 결정)
  - 인쇄(A4) 전용 레이아웃 — 화면 우선 결정에 따라 뒤로
  - 체형 세부 항목(정면 5쌍·측면 4점) 추이 — 질문 1 참고

## 데이터 영향
- **새 필드·표·localStorage 키 없음.** 대시보드는 저장하지 않고 열 때마다 `records.score/f/sd` 와 `roms.value` 에서 계산한다.
- 공유 이미지(`shares` 버킷, S3 — 회원 이름·사진 포함)에 판정·각도가 **그림으로** 더 들어가는 것은 기존과 같은 경로. 새 순수 함수는 `memberId` 를 받지 않는다(회원 필터는 호출 쪽이 이미 함).
- 비운 기록(v274~, `score`/`value` null)은 **빈 칸**으로 두고 0 으로 쓰지 않는다 — 선이 끊기고 점이 빠진다(측정한 것처럼 보이지 않게).

## 핵심 설계 결정 (왜 이렇게 하나)
| 결정 | 이유 |
|---|---|
| 회차 번호는 `mbBuildSessions()` 하나에서만 | 회차 선택 버튼이 쓰는 묶음과 같아야 "3차" 가 어디서나 같은 3차. 체형 3회차·ROM 2회차가 어긋나도 이 함수가 날짜로 맞춰 줌 |
| 판정은 기존 `scoreBand`·`scolJudge`·`romJudge` 재사용 | 대시보드와 아래 기존 표의 판정 색이 절대 어긋나지 않게. 새 임계값 없음 (ROM 평균만 90/70 경계 — `romJudge` 와 동일) |
| ROM 평균 = 측정한 항목(좌·우 따로)의 `romJudge().pct` 를 100 상한으로 평균, 항목 수 함께 표시 | 회차마다 측정 항목 수가 다르면 평균이 흔들리므로 `72% (6항목)` 처럼 n 을 보여 줌. 신전(정상 0°)은 `romJudge` 가 이미 % 를 주므로 그대로 |
| 공유 이미지는 **캔버스로 직접 그림** (SVG → 이미지 변환 안 함) | SVG 를 이미지로 올리면 글꼴이 바뀌고(IBM Plex → 시스템), 일부 기기에서 한글이 깨짐. 좌표 함수를 공유하므로 수식 중복은 없음 |
| 기존 구역은 그대로 두고 **위에 추가만** | 격자 배경·회차 삭제·ROM 삭제·PRO 잠금·전후 비교가 기존 DOM id 에 붙어 있어 손대면 회귀 위험 |
| 390px: 상태표 열 ≤5, 칸은 색+숫자만, ROM 그래프는 행마다 작은 SVG | 큰 SVG 를 줄이면 글자가 13px 아래로 떨어짐 (UI_GUIDE 3) |

## 위험과 되돌리는 법
| 위험 | 일어날 때 | 되돌리는 법 |
|---|---|---|
| 회차가 섞여 다른 날 값이 한 열에 들어감 | 체형·ROM 날짜가 다른 회원 | 회차 출처를 한 함수로 고정 + 픽스처 테스트 5종(체형 3회차·ROM 2회차 / 같은 날 2건 / 거북목만 / 비운 기록 / 같은 항목 2건). 화면 확인: 상태표 열의 날짜 = 회차 버튼 날짜 |
| 공유 이미지가 길어져 3MB 초과 | ROM 항목이 많은 회원 | 대시보드 블록 ≤ 약 1,200px, 열 ≤5·행 제한. 기존 축소·재압축 로직이 그대로 작동. 실측으로 확인 |
| 390px 가로 스크롤 | 상태표 | 라벨 100px + 칸 44px × 5 = 340px ≤ 358px. `ui-checker` 점검 |
| 기존 리포트 기능 회귀 | 격자·삭제·PRO·전후 비교 | 기존 DOM·함수는 건드리지 않음. 수정은 `buildReportPages` 첫 블록 분할과 판정 함수 한 줄 연결 2곳뿐. 각 단계 뒤 TESTING 점검표 재실행 |
| 새 js 파일을 못 받은 순간 오류 | 오프라인·캐시 전환 | `AYO_LOGIC.buildTimeline` 이 없으면 카드를 숨기고 나머지 리포트는 정상 |
| 전체 되돌리기 | 배포 후 문제 | `/rollback` — 서버 변경이 없어 코드만 되돌리면 끝 |

## 단계 (한 단계씩 확인 → 커밋)
1. **판정 함수 이동** — `romJudge`·`scoreBand` → `judge.js`, 테스트 추가. 확인: `npm test` 통과, 앱의 ROM 표·점수 색이 전과 같음
2. **시계열 순수 함수** — `buildTimeline` + 픽스처 5종 테스트, `sw.js`·script 태그. 확인: `npm test`, 리포트 열어도 콘솔 오류 없음(화면 변화 아직 없음)
3. **ROM 평균·KPI·상태표·아령 행 함수** + 테스트(신전 0° 포함, 회차 6개면 열 5개, 1차가 비면 "2차 대비"). 확인: `npm test`
4. **차트 좌표·SVG** + 테스트(빈 칸 끊김, 값 1개, 범위 밖). 확인: `npm test`
5. **KPI 타일 화면** — `#repDash` + `renderRepDash`, 불러오는 중·정상 상태. 확인: 가짜 회원(홍길동) 2회차 이상 → 타일 4개 값·판정이 아래 기존 표와 같음, 390px 가로 스크롤 없음
6. **상태표** — 선택 회차 열 강조·범례. 확인: 회차를 바꾸면 열이 1~N차로 줄고, 6회차 회원은 열 5개
7. **ROM 아령 행 + 숫자 표 토글**. 확인: 좌 파랑·우 청록·1차 회색 점, 토글로 표
8. **1회차·빈·오류 상태**. 확인: 홍길동 신규 → 체형 1회만 저장 → "첫 측정" 타일 + 1열 표; ROM 만 1회 → 점수 타일 "–"
9. **공유 이미지** — `drawRepDash` + `buildReportPages` 분할. 확인: [리포트 이미지 저장] 1쪽이 머리글→대시보드→사진, [공유 링크] 를 `r.html` 로 열어 같은 내용, ROM 12항목 회원으로 3MB 압축 통과
10. **문서·배포 준비** — DATA/ARCHITECTURE/TESTING/ADR-011/BACKLOG/CHANGELOG. `/ship` 은 사용자 확인 후

시험은 **가짜 회원(홍길동 · 010-0000-0000)** 으로만 한다.

## 확인이 필요한 질문 (최대 3개)
1. **상태표에 체형 세부 행(어깨 기울기·골반 기울기 등 정면 5쌍·측면 4점)을 넣을까요?**
