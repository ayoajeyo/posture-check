# UI 디자인 가이드 (AYOAJEYO 표준)

> 기본값은 **심플·깔끔**. 프로젝트마다 바꾸지 않는다. 바꿀 이유가 있으면 ADR 로 남기고 바꾼다.
> 코드로 옮기는 CSS 는 `.claude/skills/clean-ui/SKILL.md`. 점검은 `ui-checker` 에이전트.

## 1. 원칙
1. **덜어낸다** — 장식보다 여백. 한 화면에 강조는 하나.
2. **도구처럼 보인다** — 매일 쓰는 업무 도구. 광고 페이지처럼 꾸미지 않는다.
3. **같은 것은 같게** — 같은 뜻의 버튼은 모든 화면·모든 앱에서 같은 이름·모양·위치.
4. **한 손, 한 번에** — 폰을 한 손에 들고 엄지로 닿는 곳에 주 버튼. 자주 쓰는 행동은 탭 2번 안.

## 2. 색상
| 용도 | 값 | 쓰는 곳 |
|------|------|------|
| 포인트 (네이비) | `#1E2A4A` | 주 버튼, 선택된 탭, 제목, 링크 |
| 포인트 연한 배경 | `#EEF1F7` | 선택된 항목 배경, 정보 박스 |
| 본문 글자 | `#1F2328` | 일반 텍스트 |
| 보조 글자 | `#6B7280` | 날짜, 설명, 단위 |
| 구분선 | `#E5E7EB` | 테두리, 줄 |
| 카드·입력칸 | `#FFFFFF` | |
| 페이지 배경 | `#F7F7F5` | |
| 정상 | `#15803D` (배경 `#ECFDF3`) | 상태 표시에만 |
| 주의 | `#B45309` (배경 `#FFF7E6`) | |
| 위험·오류 | `#B91C1C` (배경 `#FEF2F2`) | 삭제 버튼, 오류 문구 |

상태색은 **의미가 있을 때만** 쓴다. 꾸미려고 쓰지 않는다. 측정 리포트의 정상/주의/개선필요 3단계도 이 세 색을 쓴다.

## 3. 글자
| 용도 | 크기 | 굵기 | 줄간격 |
|------|------|------|-------|
| 화면 제목 | 20px | 700 | 1.3 |
| 소제목·카드 제목 | 16px | 600 | 1.4 |
| 본문 | 15px | 400 | 1.6 |
| 보조·캡션 | 13px | 400 | 1.5 |
| 숫자 강조(점수·각도) | 28px | 700 | 1.1, `font-variant-numeric: tabular-nums` |

글꼴: Pretendard → Noto Sans KR → 시스템 기본. 영문·숫자도 같은 글꼴. 본문 13px 미만 금지.

## 4. 여백·모양
- 여백은 8의 배수만: 8 · 16 · 24 · 32px. 카드 안쪽 16px, 카드 사이 12px, 섹션 사이 24px.
- 모서리 10px(카드·버튼·입력칸), 6px(작은 태그), 원형(아바타·점). 세 가지 외 금지.
- 그림자 없음. 구분은 1px 선과 배경색 차이로만.
- 화면 좌우 여백 16px. 최대 폭 480px(앱) / 960px(관리·리포트 미리보기) 가운데 배치.

## 5. 컴포넌트
| 요소 | 모양 | 규칙 |
|------|------|------|
| 주 버튼 | 네이비 채움 + 흰 글자, 높이 48px, 글자 16px 600 | **화면당 1개.** 보통 화면 맨 아래 고정 |
| 보조 버튼 | 흰 배경 + 회색 테두리, 높이 44px | |
| 글자 버튼 | 네이비 글자만 | "취소", "건너뛰기" 처럼 덜 중요한 행동 |
| 위험 버튼 | 빨강 테두리 + 빨강 글자 (채움 아님) | 삭제. 누르면 반드시 확인 팝업 |
| 입력칸 | 높이 44px, 회색 테두리, 선택 시 네이비 2px 테두리 | 라벨은 위에, 예시는 placeholder 에 |
| 카드 | 흰 배경, 1px 테두리, 16px 안쪽 여백 | 카드 안에 카드 넣지 않음 |
| 목록 | 줄마다 56px 이상, 오른쪽에 `›` | 탭하면 상세. 길게 누르기 기능은 쓰지 않음(발견 못 함) |
| 탭 바(하단) | 아이콘 + 글자, 선택은 네이비 | 3~5개. 현재 위치를 항상 표시 |
| 팝업 | 흰 카드 + 반투명 검정(`rgba(0,0,0,.45)`) 배경, 블러 없음 | 제목 + 내용 + 버튼 2개(취소 왼쪽·확인 오른쪽) |
| 토스트(짧은 알림) | 화면 하단, 2초, 검정 반투명 | "저장했습니다" 같은 확인용 |
| 태그·배지 | 13px, 연한 배경 + 진한 글자, 모서리 6px | 상태 표시 |
| 체크박스·토글 | 44px 터치 영역, 선택 시 네이비 | |

## 6. 화면 상태 (모든 목록·데이터 화면에 4가지를 다 만든다)
| 상태 | 보여줄 것 |
|------|----------|
| 불러오는 중 | 회색 뼈대(스켈레톤) 또는 "불러오는 중…" 한 줄. 빙글빙글 아이콘만 띄우지 않음 |
| 비어 있음 | 한 줄 안내 + 다음 행동 버튼 1개. 예: "아직 회원이 없습니다" + [회원 등록] |
| 오류 | 무엇이 잘못됐는지 + 할 수 있는 일. 예: "저장하지 못했습니다. 다시 시도해 주세요" + [다시 시도] |
| 정상 | 내용 |

## 7. 글쓰기 (버튼·문구 표준)
존댓말, 짧게, 행동 중심. 같은 뜻은 반드시 같은 단어.

| 뜻 | 쓰는 말 | 쓰지 않는 말 |
|----|--------|-------------|
| 저장 | **저장** | 완료, 확인, 등록(새로 만들 때만 "등록") |
| 취소·닫기 | **취소**(진행 중 그만둘 때) / **닫기**(보기만 한 팝업) | 뒤로, X만 있는 버튼 |
| 삭제 | **삭제** → 확인 팝업 "정말 삭제할까요? 되돌릴 수 없습니다" [취소] [삭제] | 제거, 지우기 |
| 다음 단계 | **다음** / 마지막은 **완료** | 계속, 진행 |
| 공유 | **공유** | 보내기, 내보내기(파일 저장일 때만) |
| 인쇄·PDF | **PDF 저장** | 인쇄, 출력 |
| 촬영 | **촬영** / 다시 찍기는 **다시 촬영** | 찍기, 캡처 |
| 측정 | **측정** | 분석, 검사 |
| 펼침·접기 | **○○ 보기** / 펼친 뒤엔 **○○ 접기** (예: 숫자 보기 ↔ 숫자 접기) | 더보기, 상세, 세부, 토글 |
| 성공 알림 | "저장했습니다" | "성공적으로 저장되었습니다!" |
| 오류 알림 | "저장하지 못했습니다. 다시 시도해 주세요" | "에러 발생", 영어 메시지 |

- 느낌표·이모지는 쓰지 않는다. 메뉴·버튼 아래 설명 문구를 덧붙이지 않는다.
- 숫자 단위는 숫자 뒤에 붙인다: `2.1°`, `6.3cm`, `63점`.
- 날짜는 `2026.10.14`, 시간은 `18:54`.

## 8. 아이콘
- 선(outline) 아이콘 한 종류(예: Lucide)로 통일. 선 굵기 1.75px, 크기 20px(글자 옆) / 24px(탭 바).
- 아이콘만 있는 버튼에는 `aria-label` 과 길게 눌렀을 때 툴팁 대신 **글자를 함께** 둔다.
- 이모지를 아이콘 대신 쓰지 않는다.

## 9. 리포트(A4 인쇄·PDF)
- 용지 A4 세로, 여백 14mm. 페이지마다 머리글(앱 이름·회원·날짜·No.)과 바닥글(`made by AYOAJEYO` · 쪽번호).
- 화면용 색을 그대로 쓰되, 배경색 박스는 `print-color-adjust: exact`.
- 표·사진이 페이지 중간에서 잘리지 않게 `break-inside: avoid`.
- 글자는 본문 11pt 이상. 사진 옆 수치 표는 한 페이지 안에.
- 구현 패턴은 `report-print` 스킬.
- (v292) 리포트는 **문서 한 벌**: 머리글(센터·회원·회차·날짜·No.·담당) → 번호 섹션 01~08(요약 → 변화 → 상세 → 사진 → 기록 → 기준) → 바닥글. 화면·이미지·PDF 가 같은 순서·같은 수치. 섹션 번호는 보이는 섹션만 센다.
- 리포트 그래프 규칙: 색은 네이비 하나, 판정에만 상태색. 좌/우는 색이 아니라 줄(라벨 '좌'·'우')로 구분. 전→후는 ○(회색 테두리, 1차) → ●(네이비, 선택 회차) 한 가지 기호. 정상 범위는 연한 초록 띠. 숫자에 색을 입히지 않는다(변화량 ▲▼만 개선=초록·악화=빨강).

## 10. 접근성·기기
- 터치 영역 최소 44×44px, 버튼 사이 8px 이상.
- 글자색 대비 4.5:1 이상 (보조 글자 `#6B7280` 은 흰 배경에서 통과).
- 390px 폭에서 가로 스크롤 없음. 큰 표는 카드 목록으로 바꾼다.
- 키보드가 올라올 때 입력칸이 가려지지 않게 `scrollIntoView`.
- 다크모드는 만들지 않는다(리포트 색 일관성). `color-scheme: light` 고정.
