# 심플하지만 고급스럽게

`clean-ui` 는 **틀리지 않게**, 이 스킬은 **좋아 보이게** 만든다. 색·장식을 더하는 게 아니라 **정돈**으로 고급스러움을 만든다.
기준: `docs/UI_GUIDE.md` 가 기본, `docs/TASTE.md` 는 더 구체적인 사용자 취향이라 함께 따른다. 둘이 부딪히면 마음대로 고르지 말고 사용자에게 묻는다(필요하면 ADR). 이 스킬은 둘 다 지킨 위에서 다듬는 방법이다.

## 0. 시작 전에
1. `docs/TASTE.md` 를 읽는다 — 사용자가 이미 좋다·싫다고 한 것.
2. `design-system/styleguide.html` 에 있는 모양을 **복사**해서 쓴다. 새 모양을 만들지 않는다. (자기 CSS 가 있는 기존 앱이면 견본은 참고만 하고 앱의 기존 패턴 중 가장 정돈된 것을 따른다 — `clean-ui` "기존 앱" 참고.)
3. 글꼴은 Pretendard 를 불러온다 (`clean-ui` 의 `<link>`).

## 1. 시선 순서 — 화면마다 1·2·3순위를 먼저 정한다
| 순위 | 예 (측정 결과 화면) | 표현 |
|------|------------------|------|
| 1 | 종합 점수 `63점` | 28px 700, 네이비 또는 본문색, 위쪽 |
| 2 | 항목별 결과 카드 | 16px 600 제목 + 15px 본문 |
| 3 | 날짜·설명·단위 | 13px 보조색 |
차이는 **크기·굵기·회색 단계**로만 낸다. 색·상자·아이콘을 더해 강조하지 않는다. 1순위는 화면에 하나.

## 2. 정렬 — 보이지 않는 세로선
- 화면 왼쪽 여백 16px 선 하나에 제목·카드·목록 글자를 모두 맞춘다. 가운데 정렬은 빈 화면 안내와 제작자 표기 정도만.
- 숫자 열은 오른쪽 정렬 + `tabular-nums` 로 자릿수를 맞춘다.
- 아이콘은 글자 높이 가운데에, 글자와 8px 간격.

## 3. 여백 리듬 — 가까움으로 묶는다
- 한 묶음 안 8px, 카드·요소 사이 16px, 묶음과 묶음 사이 24px, 화면 위아래 32px. **사이 간격이 안 간격보다 항상 크게.** (tokens: `.stack-tight` 8 · `.stack` 16 · `.section` 24)
- 줄을 긋기 전에 여백으로 나눠 본다. 선은 목록 줄 구분에만.
- 카드 안쪽 16px. 카드 안 요소가 3개를 넘으면 요소 사이를 8→16px 로 넓혀 숨 쉬게.

## 4. 밀도 — 한 화면에 할 일 하나
- 첫 화면에 보이는 카드는 5개 안팎. 넘치면 접기(펼치기 1번)나 상세 화면으로.
- 한 카드에는 한 가지 이야기. 숫자 3개 이상이면 표나 목록으로.
- 설명 문장은 한 줄. 두 줄이 필요하면 화면 구성이 틀린 것.

## 5. 글자 디테일
- 제목 `letter-spacing: -0.02em`, 본문 `-0.01em` (Pretendard 는 살짝 좁혀야 단정해 보인다).
- 한글 줄바꿈 `word-break: keep-all` — 단어가 반으로 갈리지 않게 (tokens.css 에 들어 있음).
- 숫자 강조 옆 단위는 작게·보조색: `63` + `점`(15px 회색). 각도 `°` 는 숫자와 같은 크기로 붙인다.
- 회색은 3단계만: 본문 `--text`, 보조 `--muted`, 선 `--line`. 중간 회색을 새로 만들지 않는다.

## 6. 사진·그림
- 사진은 비율을 고정한다 (`aspect-ratio: 3/4; object-fit: cover`). 모서리 10px, 바탕 `--page`.
- 사진 위 점·선은 2px 흰 테두리를 둘러 어떤 배경에서도 보이게 (`measure-viz`).
- 아이콘은 선 아이콘 한 종류, 20px, 선 굵기 1.75px.

## 7. 손에 닿는 느낌
- 누르면 `opacity: .85` (tokens.css). 선택 상태는 `--ink-soft` 배경 + 네이비 글자.
- 주 버튼은 화면 아래 고정(`.bottom-bar`) — 엄지가 닿는 곳. 위험 버튼은 주 버튼 자리에 두지 않는다.
- 저장·삭제 후에는 토스트 한 줄("저장했습니다"). 화면 전체를 다시 그려 깜빡이지 않게.

## 8. 빈·오류·로딩도 디자인이다
- 빈 화면: 지금 상태 한 줄 + 다음 행동 버튼 하나 (`.state`). 그림·이모지 넣지 않는다.
- 오류: 무엇이 안 됐는지 + 할 수 있는 일 + [다시 시도]. 기술 용어·영어 금지.
- 로딩: 회색 뼈대(`.skeleton`)를 실제 내용 모양대로.

## 9. 밋밋할 때 처방표
| 증상 | 원인 | 처방 |
|------|------|------|
| 다 비슷해 보인다 | 위계 없음 | 1순위 하나를 28px 로, 나머지는 줄인다 |
| 어수선하다 | 간격이 다 같음 | 묶음 안 8 · 묶음 사이 24 |
| 휑하다 | 요소가 화면 위에만 몰림 | 주 버튼을 아래 고정, 카드 폭을 꽉 채움 |
| 싸 보인다 | 기본 글꼴·회색 남발 | Pretendard + 회색 3단계 + 제목 자간 |
| 답답하다 | 선과 상자가 많음 | 선을 지우고 여백으로 나눔, 카드 안 카드 제거 |
| 숫자가 안 읽힌다 | 단위·숫자 크기 같음 | 숫자 크게·단위 작게, tabular-nums |

## 10. 마감 점검 (끝내기 전 10가지)
1. 1순위가 한눈에 보이나 2. 왼쪽 선이 하나로 맞나 3. 묶음 사이 > 묶음 안 간격인가 4. 주 버튼이 하나인가 5. 회색이 3단계뿐인가 6. 숫자가 tabular 인가 7. 390px 에서 가로 스크롤·잘림이 없나 8. 4가지 상태가 다 있나 9. 버튼 이름이 UI_GUIDE 7번 단어인가 10. `docs/TASTE.md` 와 어긋나는 곳이 없나

끝나면 `python scripts/screenshot.py {화면}` 으로 찍어 직접 보고, `ui-designer` 에게 개선안을 받는다.

## 11. 취향 기록
사용자가 디자인에 대해 "좋다·싫다·이렇게 해 줘" 라고 하면 **그 자리에서** `docs/TASTE.md` 기록 표에 한 줄 남긴다 (날짜 · 화면 · 반응 · 사용자 말 그대로 · 앞으로의 규칙). 같은 말이 두 번 나오면 "확정 취향" 으로 올린다.
